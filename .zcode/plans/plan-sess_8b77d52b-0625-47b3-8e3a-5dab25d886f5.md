# Plan: Mobile/Desktop se Agent Control + Info Entry (WiFi)

## Goal

Abhi PWA dashboard (`web/`) sirf `localhost:5201` pe chalta hai — phone se nahi khulta. Is plan se:

1. **Phone/laptop (same WiFi) se dashboard khulega** — LAN binding + API key auth + login screen
2. **Control features** jo abhi backend mein missing hain: uploads pause/resume/retry/cancel, folder rescan, timetable sync pause/"sync now", lecture re-match, overrides list/undo
3. **Info entry improve hogi**: timetable mein slot add (already hai) + real room list + slot cancel (override) + undo
4. Internet-se-control (Firebase Phase 4) **baad ke liye foundation** — ek hi jagah config, auth headers centralized

## Part 1 — Backend: Network + Auth

**Files: `agent/src/LectureAgent/Program.cs`, `Security/ApiKeyMiddleware.cs`, `appsettings.json`, `scripts/run-agent.sh`**

- `Program.cs`: `UseHttpsRedirection()` hatao (phone pe self-signed cert redirect ka bad experience hota hai; dono endpoints explicitly configured hain). Baaki middleware order same.
- `ApiKeyMiddleware.cs`: public paths mein add karo — `/assets`, `/manifest.json`, `/favicon.svg`, `/icons.svg` (PWA shell load ho sake). `/api/monitor` ko public list se **hatao** (LAN pe leak na ho; PWA ab key bhejega). `/health` public rahega.
- `run-agent.sh`: env se set karo — `Kestrel__Endpoints__Http__Url=http://0.0.0.0:5200`, `Kestrel__Endpoints__Https__Url=https://0.0.0.0:5201`, `Auth__Enabled=true`, aur `Auth__ApiKey` (env `AGENT_API_KEY` ho to woh, warna random generate karke console pe print). LAN IPv4 URLs bhi print karo (macOS `ipconfig getifaddr`, Linux `hostname -I` best-effort) taaki user phone se wahi URL khole.
- `appsettings.json` default localhost + auth-off hi rahega (dev safe); LAN sirf run script se.

## Part 2 — Backend: Control Endpoints

**New: `Services/AgentControlState.cs` (singleton bool flags), `Controllers/ControlController.cs`, `Controllers/AgentInfoController.cs`; edits: `UploadProcessingService.cs`, `FileMonitoringService.cs`, `TimetableSyncBackgroundService.cs`, `Infrastructure/FileWatching/FileWatcher.cs` + `Domain/Services/Interfaces.cs`, `Domain/Enums/EnumTypes.cs` (`UploadStatus.Cancelled = 6`), `Application/Services/ApplicationServices.cs`**

- Singleton **`AgentControlState`**: `UploadsPaused`, `MonitoringPaused`, `TimetableSyncPaused` (+ pausedAt/reason).
- **Uploads**: `POST /api/control/uploads/pause|resume` → `UploadProcessingService.ProcessQueueAsync` loop ke top pe flag check. `POST /api/control/uploads/{id}/retry` → Status=Pending, NextRetryAt=null, RetryCount=0 (FailedPermanently se bhi) + audit log. `POST /api/control/uploads/{id}/cancel` → `UploadStatus.Cancelled` (sirf Pending/Failed/FailedPermanently pe; Uploading pe 409). `POST /api/control/uploads/retry-failed` → bulk retry.
- **Monitoring**: `POST /api/control/monitoring/pause|resume` → `FileMonitoringService.OnFileDetected` gate (pause ke dauraan naye files skip). `POST /api/control/rescan` → `FileWatcher` mein `ScanExisting()` public method (Start() ke andar wala initial-scan logic extract karke) + re-entrancy guard.
- **Timetable sync**: `POST /api/control/timetable/sync` → turant `TimetableSyncService.SyncTimetableAsync(centerId)`. `POST /api/control/timetable/sync/pause|resume` → background service tick pe flag check.
- **Lectures**: `POST /api/lectures/{id}/rematch` → existing session pe `MatchingService.AnalyzeAndAssignAsync()`.
- **Overrides**: `GET /api/timetable/overrides?centerId=&date=` (active list) + `POST /api/timetable/overrides/{id}/deactivate` (IsActive=false) — PWA se undo possible.
- **Info**: `GET /api/agent/info` → version, center/room, monitor folder, drive mode, sheet-sync interval, LAN URLs, uptime (Settings UI ke liye).
- Saare mutating endpoints audit log karenge (existing `IAuditLogger` pattern).

## Part 3 — PWA (web/src)

**Refactor: `App.tsx` (705 lines) → `src/ui.tsx` (Card/Pill/Modal/Button/Toast — existing copy-paste patterns) + `src/screens/Live.tsx`, `Review.tsx`, `Schedule.tsx`, `Controls.tsx`; new `src/config.ts` + `Login.tsx`; `api.ts` rewrite headers**

- **`api.ts`**: har request pe `X-Agent-Key` header (`localStorage.agentApiKey` se); optional absolute agent URL (`localStorage.agentUrl`, default same-origin — Firebase phase ke liye foundation); 401 pe login screen trigger; naye control endpoints ke functions.
- **`Login.tsx`**: Agent URL + API key form, "Connect" `GET /health` se test karta hai, save karta hai localStorage mein. Pehli baar ya 401 pe dikhega.
- **New "Controls" tab** (Settings ki jagah): Upload engine pause/resume, Monitoring pause/resume + "Rescan now", "Retry all failed", Timetable sync pause/resume + "Sync from Google Sheet now" (wipe-warning ke saath), Agent info card (folder, Drive mode, LAN URLs + copy), Connection card (key change/logout).
- **Live tab**: queue items pe Retry/Cancel buttons (failed/pending pe), paused banner.
- **Review tab**: per-lecture "Re-match" button.
- **Schedule tab**: hardcoded rooms (603/501/101) hatao — rooms timetable data se derive karo; slot pe "Cancel" (→ `OverrideType.Cancelled` override) + aaj ke active overrides ki list with Undo. centerId inconsistency fix (`CENTER_001` vs `'Pune - PCMC Vidyapeeth'`) — ek `config.ts` constant jo `/api/agent/info` se aayega.
- Polling: 4s poll sirf Live tab pe (jab page visible ho); baaki tabs refresh/focus pe fetch.

## Security notes

- LAN pe HTTP plaintext hoga (API key protect karta hai but encrypt nahi) — home/center WiFi ke liye acceptable; chahe to phone `https://...:5201` cert-warning ke saath use kar sakta hai.
- `google_credentials.json` ka secret already expose ho chuka hai (SETUP_REQUIRED.md ke mutabik) — rotate karna zaroori hai, is plan ke dauran commit nahi hoga.
